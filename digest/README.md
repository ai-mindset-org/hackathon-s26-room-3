# digest

Модуль участника **MG7S**. Генератор **дайджеста недели** из сырых заметок по
канону. Закрывает приёмочный пример `examples/03-дайджест`.

В отличие от `canon-lens`/`judge` (они проверяют текст), `digest` **порождает**
контент, а затем прогоняет результат через тот же движок канона как self-check.

## Что делает

Вход — сырые заметки (строка на день/событие). Выход — дайджест:
- заголовок со строчной, 3–5 пунктов, каждый ≤ 2 строк;
- только события, значимые для читателя (внутренний спор без решения — опустить
  или дать как «решение ожидается»);
- плохие новости (срывы, переносы) не прячутся;
- без эмодзи и антитез.

Канон дайджеста — **свой файл** `canon.digest.md`: отличается от канона поста
(в дайджесте числа не требуют источника — источник сами заметки; нет лимита
1200 знаков и запрета CTA; добавлен контроль числа пунктов). Меняешь файл →
меняется поведение, кода не трогаешь.

## Запуск

```bash
# из корня репозитория:
PYTHONPATH=digest python -m digest.cli make <файл-заметок> [--check]
PYTHONPATH=digest python -m digest.cli make <файл> --offline --check   # без LLM

# приёмочный пример:
PYTHONPATH=digest python -m digest.cli make examples/03-дайджест/input/заметки-недели.txt --check

# тесты (детерминированные, оффлайн):
python digest/tests/test_digest.py    # PASS 6/6
```

`--check` прогоняет результат через `canon-lens` по `canon.digest.md` и печатает
число нарушений в stderr (self-check порождённого контента).

### LLM-runtime

По умолчанию — локальный **`claude` CLI** headless (ключ API не нужен),
провайдер сменяем `--llm-cmd`. Для приёмки/CI без сети — `--offline`
(дайджест берётся из `<файл>.digest.md` рядом со входом).

## Проверка на приёмке

Живой прогон на `examples/03-дайджест/input/заметки-недели.txt` даёт дайджест,
совпадающий с `expected.md` по фактам (тёмная тема · 120 регистраций · саппорт
6ч→2ч · срыв интеграции упомянут честно · спор про цену как «решение ожидается»)
и проходящий `canon.digest.md` с 0 error.

Только stdlib (Python ≥ 3.11). Папка изолирована. Секретов в репозитории нет.

## Отношение к другим модулям

- `canon-lens` (HA59) — движок проверки канона; `digest` зовёт его для self-check.
- `judge` (MG7S) — смысловая проверка; тот же канон-файловый подход.
