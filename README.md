# Комната 3 · Контент-конвейер по канону

Хакатон AI Mindset S26 «Чужая боль» · 29.08.2026 · 10:00–14:00 CET

## Задача

Команда строит инструменты для подготовки контента из сырья по канону.
Канон хранится в файлах и меняет поведение без изменения кода.

Основные сценарии:

- Сценарий рилза из статьи или заметок.
- Дайджест недели из сырых событий.
- Проверка текста с точным местом каждого нарушения.
- Единый отчёт из механических и смысловых находок.

Репозиторий содержит несколько самостоятельных модулей. Они используют общие
каноны и контракты, но пока не образуют один универсальный CLI.

## Основные реализации

### `reels/` — сценарии рилзов

[`reels/`](reels/) получает статью, извлекает факты и создаёт сценарий с
отчётом. Сборщик использует только подтверждённые факты и отдельно ищет числа
вне источника. На рутинном сырье модуль может отказаться от генерации.

Сквозной запуск:

```bash
python reels/run.py reels/input/sostav-86369.md
```

Результат находится в `reels/out/<id>/`:

- `facts.json` — факты и дословные цитаты.
- `script.md` — сценарий рилза.
- `report.md` — нарушения, происхождение фактов и хронометраж.

Подробности и ограничения находятся в [`reels/README.md`](reels/README.md).

### `canon-lens/` — проверка текста по канону

[`canon-lens/`](canon-lens/) выполняет детерминированную проверку. Каждая
находка содержит пункт канона, цитату, строку, колонку и абсолютный сдвиг.

```bash
PYTHONPATH=canon-lens python -m canon_lens.cli check <файл> \
  --canon canon-lens/canon.md --json
```

Канон является входным файлом. Для другого канона не требуется изменение
кода. Формат канона и находок описан в
[`canon-lens/CONTRACTS.md`](canon-lens/CONTRACTS.md).

Модуль [`judge/`](judge/) дополняет буквальные правила смысловой проверкой.
Модуль [`report/`](report/) объединяет их находки по общему контракту
`Violation`.

Общий воспроизводимый прогон без LLM:

```bash
python report/e2e.py
```

### `digest/` — дайджест недели

[`digest/`](digest/) получает сырые заметки и создаёт короткий дайджест.
Модуль сохраняет важные события, не скрывает плохие новости и исключает
внутренний шум. После генерации он проверяет результат через `canon-lens`.

```bash
PYTHONPATH=digest python -m digest.cli make \
  examples/03-дайджест/input/заметки-недели.txt --check
```

Для воспроизводимого запуска без LLM добавьте `--offline`. Правила дайджеста
находятся в [`digest/canon.digest.md`](digest/canon.digest.md).

## Как связаны модули

```text
статья → reels/extract → facts.json → reels/compose → script.md + report.md
                                      ↑
                                 canon-lens

текст → canon-lens ─┐
                    ├→ report → единый отчёт
текст → judge ──────┘

заметки → digest → черновик → canon-lens → self-check
```

`reels`, `canon-lens` и `digest` являются основными продуктовыми
реализациями. `judge` и `report` расширяют проверку и собирают общий отчёт.

## Matt — резервная реализация

[`matt/`](matt/) — второй вариант для быстрой и полностью офлайн-приёмки.
Он детерминированно обрабатывает три канонических примера `01–03` и не требует
LLM или сети.

```bash
python3 matt/run.py accept examples --canon examples/canon.md
```

Matt полезен как резерв для демо и регрессионной проверки. Он не является
основной архитектурой и не предназначен для произвольных входов. Дополнительный
пример `04-ai-practiq-content` не входит в его текущую границу приёмки.

## Приёмка

Папка [`examples/`](examples/) содержит входы и ожидаемые результаты. Результат
сверяется с `expected.md` по смыслу и фактам.

- `01-вычитка` проверяет поиск нарушений и исправленный черновик.
- `02-рилз` проверяет сценарий, факты из источника и один CTA.
- `03-дайджест` проверяет отбор событий и соблюдение канона.
- `04-ai-practiq-content` является дополнительным заданием и не входит в
  текущую автоматическую приёмку Matt.

Основные модули проверяются своими командами и тестами. Matt даёт резервный
прогон канонических примеров `01–03` одной командой.

## Ограничения

- Общего CLI для всех модулей пока нет.
- `canon-lens`, `digest`, `judge` и `report` требуют Python 3.11.
- Live-режимы `judge` и `digest` используют локальный `claude` CLI.
- Офлайн-режимы используют фикстуры и подходят для воспроизводимой проверки.
- Matt поддерживает только три канонических типа входа.

## Работа с репозиторием

Перед изменением кода прочитайте [правила для агентов](AGENTS.md) и
[регламент координации](docs/agent-coordination.md).

- Создайте Issue и укажите владельца, пути и критерии приёмки.
- Создайте ветку от актуального `main`.
- Изменяйте только назначенный модуль или папку.
- Запустите применимые примеры и тесты.
- Откройте PR и приложите результат проверки.
- Не добавляйте секреты, ключи или приватные материалы.

Интервью с заказчиками находятся в [`docs/`](docs/). Они объясняют исходные
боли, критерии качества и границы решения.
