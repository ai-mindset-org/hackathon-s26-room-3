# Комната 3 · Контент-конвейер по канону

Хакатон AI Mindset S26 «Чужая боль» · 29.08.2026 · 10:00–14:00 CET

## Задача

Из сырья — видео-зарисовок, черновиков, данных проекта — нужно регулярно
делать контент: рилзы, дайджесты, раздаточные материалы. Ручная доводка
и вычитка съедает часы, а канон (стиль, правила, запреты) живёт в голове.

**Строим:** конвейер, который берёт сырьё + описанный канон и отдаёт черновик
контента (сценарий рилза, дайджест недели, вычитанный документ) с отчётом,
что в исходнике канону не соответствовало. Канон — файл в репо, меняется без
правки кода.

Боли заказчиков: конвейер рилзов из видео-зарисовок и контекста продукта;
дайджест для компании; ручная вычитка маркетинговых материалов; каноны
маркетинговых документов; монтажные тизеры со встреч.

## Как работаем с кодом

- **Fork → ветка → PR.** Агент делает это сам: `gh repo fork ai-mindset-org/hackathon-s26-room-3 --clone`,
  ветка `КОД-УЧАСТНИКА/что-делаю`, `gh pr create --fill`. Мержит лидер комнаты.
- **Один участник — один модуль или папка.** Кто что берёт — решаем в комнате,
  фиксируем issues. Так PR не дерутся между собой.
- Конфликт: `git remote add upstream https://github.com/ai-mindset-org/hackathon-s26-room-3` →
  `git pull --rebase upstream main`.
- Интервью с заказчиками кладём в `docs/interview-КОД.md`.
- **Секретов в репозитории не бывает.** Репо публичный. `.env` в `.gitignore`,
  ключи живут только на вашей машине.
- После каждого мержа гоняем `examples/` — они и есть приёмка.

## Приёмка

В `examples/` лежат входы с ожидаемым результатом (появятся к утру события,
собраны из болей заказчиков). Итог демо: «прошло N из M» + вердикт заказчиков
«решило / не решило». Частичный результат — тоже результат.
