# judge

Модуль участника **MG7S**. Смысловая проверка текста против **канона-файла**
через LLM. Добирает то, что детерминированный `canon-lens` ловит только
буквально.

## Что делает

`canon-lens` ловит нарушения канона в буквальной форме (regex, списки слов).
Смысловые вариации — перефраз, интонация, скрытое противопоставление,
«обложка увереннее текста» — буквальным поиском не берутся. Их добирает `judge`:

- отбирает из канона **судейские** правила:
  - `judgment_extends = true` — буквальное уже поймал `canon-lens`, judge ищет
    только смысловые **вариации**;
  - `kind = "judgment"` — чисто смысловое правило, буквального аналога нет
    (`canon-lens` такой `kind` молча пропускает);
- одним LLM-вызовом на текст получает находки `{quote, reason, fix, confidence}`;
- **детерминированно** привязывает дословную цитату к `offset` в тексте
  (точное вхождение или с точностью до пробелов) — как `canon-lens`;
- выдаёт объекты той же формы `Violation` с `kind = "judgment"`.

Канон — данные, не код: тот же `canon.md`, что у `canon-lens`. Меняешь канон →
меняется поведение. Кода трогать не нужно.

## Запуск

```bash
# из корня репозитория, папка модуля в PYTHONPATH:
PYTHONPATH=judge python -m judge.cli check <файл> [--canon canon-lens/canon.md] [--json]

# оффлайн (без LLM): вердикт берётся из <файл>.judge.json рядом с входом
PYTHONPATH=judge python -m judge.cli check <файл> --offline --json

# тесты (только stdlib, детерминированные, без сети):
python judge/tests/test_anchor.py     # PASS 5/5  — якорение цитаты в offset
python judge/tests/test_offline.py    # PASS 6/6  — форма Violation, offset, contract
python judge/tests/test_contract.py   # PASS 5/5  — устойчивость ядра
```

Код возврата `check`: `1` если есть нарушения `severity=error`, иначе `0`.

### LLM-runtime

По умолчанию — локальный **`claude` CLI** (Claude Code) в headless-режиме
(`-p --output-format json`), ключ API не нужен. Провайдер сменяем:
`--llm-cmd <команда>` — любой CLI, читающий промпт и печатающий текст ответа.
Нет CLI или нужен воспроизводимый прогон — `--offline` (фикстура-вердикт).

## Форма выхода — контракт `canon-lens`

`--json` даёт `{file, summary, violations[]}`, `violations[]` — те же поля, что у
`canon-lens` (`CONTRACTS.md §2`), с `kind = "judgment"` и опциональным
`confidence` (0..1). `report/` мёржит механические и судейские находки по
`offset`; `lens/` подсвечивает спаны; `rewrite/` берёт `offset` + `fix`.

Пример:

```json
{
  "rule": "no-antithesis", "point": 3, "category": "canon",
  "severity": "error", "kind": "judgment",
  "line": 3, "col": 46, "end_col": 103, "offset": [78, 135],
  "quote": "Но дело совсем не в скорости. Куда важнее предсказуемость",
  "message": "антитеза «не X, а Y» (п.3): скрытая антитеза в непрямой форме",
  "fix": "Главное в агенте — предсказуемость результата.",
  "confidence": 0.85
}
```

## Границы

- Недетерминированность LLM: для приёмки и CI — `--offline`; live-режим для демо
  и реальной работы.
- Находка привязывается по **дословной** цитате модели. Не нашлось точное
  вхождение — ищется с точностью до пробелов; совсем не нашлось → запись уровня
  документа (`offset=[0,0]`), находка не теряется.
- Модель не может выдумать правило: находка на `rule_id` вне канона отбрасывается.
- Прозаический канон (`examples/canon.md` без toml-блока) судейских флагов не
  несёт → judge на нём осознанно ничего не делает.

## Отношение к другим модулям

- `canon-lens` (HA59) — буквальные нарушения. judge — смысловые, в той же форме.
- `report/`, `rewrite/`, `lens/` — потребители общего контракта `Violation`.
