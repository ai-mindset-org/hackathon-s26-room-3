# reels — сценарий рилза из статьи по канону

Кусок комнаты по модальности «рилс». Ведут JKRK (`tonclap`, сборщик и приёмка)
и Алексей Павлов (`meta1ex`, экстрактор). Контракт между ними — `CONTRACT.md`.

```
статья --[tools/fetch_article.py]--> input/*.md --[extract/]--> facts.json --[compose/]--> script.md
                                                                  canon.md ----^            report.md
```

## запуск

```bash
python reels/tools/fetch_article.py 86369            # скачать статью в reels/input/
python -m reels.compose <facts.json> <canon.md> -o reels/out/<id>/
```

Python 3, только стандартная библиотека — чтобы кусок подключался к общему CLI
без установки зависимостей. Проверено на 3.10.

```bash
python -m reels.compose reels/compose/tests/facts.sample.json examples/canon.md -o reels/out/sostav-86369/
python -m reels.compose reels/compose/tests/facts.silence.json examples/canon.md -o reels/out/routine-day/
```

## что здесь сделано и чем это проверяется

**Сборщик не может выдумать факт.** Он собирает сценарий только из `facts.json`,
по `id`, и не видит исходного текста вовсе. Отдельная проверка `outside_source`
пересчитывает все числа произносимой части сценария по фактам: число, которого
нет ни в одном `text`, `value` или `quote`, попадает в отчёт в раздел «факты вне
источника». Это ключевая проверка приёмочного примера `02-рилз` — «цифр, которых
нет в заметках, в сценарии нет» — закрытая механически, а не обещанием промпта.

**Инструмент умеет промолчать.** `facts.silence.json` — рутинное сырьё, из
которого контент делать не надо. На нём `script.md` не создаётся вовсе, а в
`report.md` стоит `контента нет` с причиной. Код возврата ноль: отказ штатный
результат, а не ошибка. Ни один из трёх приёмочных примеров комнаты отказ не
проверяет, поэтому фикстура лежит здесь.

**Канон меняется без правки кода.** Если доступен `canon-lens/` (HA59) —
работаем через него. Иначе включается запасной разбор прозаического
`examples/canon.md`: запрещённые слова, канцелярит и лимиты длины читаются из
самого файла. Каким движком собрано, написано в отчёте строкой
`движок канона`.

## известное ограничение

`canon-lens` импортирует `tomllib`, который появился в **Python 3.11**. На 3.10
модуль не поднимается вообще, и его тесты не собираются. Пока это так, на 3.10
работает запасной разбор, а TOML-канон комнаты прочитать нельзя — попытка даёт
явную ошибку и код возврата 2. Молчаливого «канон пройден» на непрочитанном
каноне здесь не бывает: это было бы худшим из возможных поведений — пустой
набор правил проходит любой текст.

## файлы

| Путь | Что |
| --- | --- |
| `CONTRACT.md` | договор между экстрактором и сборщиком |
| `tools/fetch_article.py` | единственное место с выходом в сеть |
| `input/` | сырьё текстом: три статьи блога AI Practiq |
| `compose/build.py` | отбор фактов, сборка сценария, отчёт, отказ |
| `compose/lens.py` | адаптер к движку канона с запасным разбором |
| `compose/canon.py` | запасной разбор прозаического канона |
| `compose/tests/` | фикстуры входа: обычная и на отказ |
| `fixtures/` | образцы выхода, на которые смотрит экстрактор |
| `out/` | результаты прогона, в git не попадают |
