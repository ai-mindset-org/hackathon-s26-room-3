## Зачем вообще пишутся статьи (цель, не форма)

Это определяет, что значит «решило» для конвейера: черновик должен работать
на цель ниже, а не просто быть «хорошо написанным текстом».

**Клубный блог (Sostav и другие площадки) — SEO-акизиция в воронку.**
Статья не самоцель — это вход в воронку: SEO-трафик → подписка на
Telegram-канал → покупка курса Claude Code. Канал — главный актив, курс —
монетизация, статьи приводят туда людей, которые сами через поиск канал и
курс не найдут.

- Claude Code — тема-приманка, не суть клуба (AI Practiq — сообщество
  предпринимателей, не курс по одному инструменту). Тема выбрана из-за
  спроса в поиске и низкой конкуренции.
- Sostav сознательно сужен до кластера Claude Code — из-за высокого DR
  (~55-60) и индексации за сутки: быстрый предсказуемый трафик по узкой
  теме.
- Каждая статья опирается на реальный кейс участника клуба — соцдоказательство
  плюс уникальный материал, которого нет у конкурентов.
- Ресёрч 11.08.2026: SEO-стратегия работает, трафик статьи приносят. Падение
  роста подписчиков канала объясняется скорее воронкой (статья → канал), а
  не качеством/количеством статей — слабое звено может быть не в контенте.

**Важное уточнение (29.08, от заказчика).** Личный блог Тимура Яковлева и

## Что это значит для конвейера

- Черновик контента должен сохранять кейс-ориентированность и честные
  оговорки — это часть канона, не только формальные правила из `canon.md`.
- Критерий «решило» для заказчика — не только «текст соответствует канону»,
  но и «текст выполняет функцию в воронке» (SEO-крючок к каналу). Это стоит
  уточнить у заказчика отдельно при демо: как
  проверять это автоматически или это остаётся ручной оценкой.

**[103149](https://www.sostav.ru/blogs/289407/103149)** — статья про выбор

Обложка нарушает канон: создаёт ложное впечатление точности там, где

Это конкретный кейс для правила конвейера «обложка не должна быть точнее и
увереннее, чем текст».

## Обложки статей — процесс генерации

### Процесс

Обложка — не отдельная картинка под каждую статью, а результат
автоматического рендера: HTML-шаблон + Node.js/Puppeteer собирают готовый
PNG 1200×630. Ручной отрисовки на этом этапе нет.

Два независимых генератора, выбор зависит от площадки публикации:

- **Текстовый шаблон.** На вход — JSON с заголовком (в две строки),
  подзаголовком, до трёх коротких тегов и путём к иллюстрации. Размер
  шрифта и раскладка подстраиваются автоматически под длину текста.
- **Генератор чистой сцены (без текста).** На вход — только имя заранее
  заготовленной композиции. Никакого текста и стоковых фото — сцена
  рисуется кодом (геометрические фигуры) в фирменной палитре.

Источник иллюстрации для текстового варианта — поиск по бесплатным
фотобанкам (Pixabay основной, Openverse запасной). Правило запроса: искать
не тему статьи буквально, а предметы/сцену, которые в ней реально
участвуют — иначе выдаёт стоковое клише. Пустой результат поиска не даёт
пустую заглушку — подключается запасной генератор геометрических фигур
внутри шаблона.

Для безтекстового варианта иллюстрация не ищется — композиция выбирается
вручную под смысл статьи из библиотеки сцен; новая тема — новая
функция-сцена дописывается в тот же файл.

Рендер завершается с ошибкой и списком проблем, если текст не помещается в
холст — обрезанный вариант никогда не уходит «по умолчанию».

### Правила и канон

- Единая фирменная палитра на всей серии (тёмный градиентный фон, один и
  тот же акцентный градиент) — обложки разных статей должны узнаваться
  рядом как одна серия.
- Тип обложки жёстко зависит от площадки:

  | Площадка | Требование к обложке |
  |---|---|
  | Собственный блог, Telegram, деловая соцсеть | текст + иллюстрация, без ограничений |
  | Sostav | запрещены изображения с текстом, стоковыми фото и логотипами — только чистая композиция |
  | Timeweb | схема/скриншот по теме, без текста поверх |
  | Дзен | формат карточки жёстко регламентирован площадкой — единственный случай, где нарушение формата напрямую урезает охват |

- Контраст текста — обязательное правило, не «на глаз»: основной текст на
  тёмном фоне только белый/почти белый, тёмно-серый текст на тёмном фоне
  запрещён категорически.
- Минимальный размер шрифта заголовка и минимальный порог контраста
  зафиксированы числом, а не оцениваются интуитивно.
- Обложка статьи с реальным кейсом резидента клуба (портрет + одна цифра)
  идёт по отдельному шаблону — типовая обложка не используется: одинаковый
  баннер с разным текстом визуально сливается в одну карточку в списке.
- На ранжирование в поисковой выдаче тип обложки не влияет (официальная
  позиция Google) — правила выше касаются только модерации площадки и
  восприятия в её ленте.

### Типичные ошибки (антипримеры)

- **Стоковая иллюстрация не по теме** — фотобанк подбирает generic-иконки
  (шестерёнки, роботы, рукопожатия) на абстрактные технические понятия.
- **Обложка вообще без иллюстрации** — способ избежать проблему поиска, а
  не решить её; читается как заглушка.
- **Низкий контраст, мелкий текст** — из-за слишком прозрачных базовых
  стилей дизайн-системы; при беглом просмотре незаметно, при внимательном
  читается как брак.
- **Три одинаковых текстовых блока без иерархии** — без одного
  доминирующего элемента макет воспринимается как generic-шаблон.
- **Текст на изображении там, где площадка это прямо запрещает** — риск
  отклонения на модерации без пользы для читателя, так как на ранжирование
  текст на обложке не влияет.

### История решений (кратко)

Путь: полностью ручная сборка → дублирующиеся скрипты под разные случаи →
неудачная попытка внешнего AI-сервиса (убрана) → готовые библиотеки
иллюстраций (обе отклонены — по лицензии/авторству или несовпадению
стиля) → параметризация в единый HTML-шаблон с шестью переменными →
добавлен автопоиск иллюстраций по фотобанкам → отдельный
режим-без-текста под требования конкретной площадки → переход от поиска
фото к генерации сцены кодом (текущее решение), так как поиск стабильно
выдавал одну и ту же generic-иллюстрацию на абстрактные темы.

**Открытый вопрос:** для площадок, где обложка всё ещё идёт с текстом и
найденной иллюстрацией, автоматической проверки «подходит ли картинка
теме» нет — решение принимается вручную в момент сборки.
