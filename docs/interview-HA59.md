## Заказчик A (Тимур / Григорий — уточнить)

### Описание задачи (со слов заказчика)

Работает с AI-агентами часами каждый день вместе с друзьями, но находками не
обмениваются. Публичные каналы выпали из обихода — не постят и не читают. При
личной встрече всегда выясняется, что делиться есть чем, а механизма нет.

**Три причины, почему дыра не закрылась сама:**
1. писать пост руками в эпоху агентов — странно;
2. публиковать лог сессии — небезопасно;
3. саммаризация лога в читаемый пост нетривиальна, «в лоб» не работает.

**Масштаб (измерен, срез за сутки 28.08, его машина):**
27 файлов транскриптов сессий · 40.4 МБ · 511 правок файлов агентом ·
41 коммит по 15 репозиториям · опубликованных находок — **ноль**.

**Читатель:** 5–15 конкретных приятелей, сами целыми днями в агентах.
- НЕ нужен контекст «что такое Claude Code»;
- нужна **дельта к их опыту**;
- НЕ нужен отчёт о продуктивности;
- нужно то, **что они завтра сделают иначе**.
- Канал приватный и адресный. Публичная лента — не цель.

**Единица продукта — находка.**

### Что это значит для инструмента

- Ближе всего к режиму **дайджест**, но по сути свой формат: `лог сессии → пост-находка`.
- Вход тяжелее, чем в synthetic examples: JSONL-транскрипты + `git log` + лог правок, не «заметки с созвона».
- **Безопасность публикации — часть приёмки** (причина №2 — главный блокер): вычистить пути, токены, имена приватных репо, .env, e-mail, IP.
- Канон этого заказчика (доп. к `examples/canon.md`):
  - единица = находка (список дискретных находок, не проза);
  - без онбординг-контекста («что такое X», «как известно»);
  - каждая находка → конкретное «сделаю иначе»;
  - без отчёта о продуктивности / метрик ради метрик;
  - тон — для своих, приватный.

### Уточняющие вопросы (следующий заход)

- [ ] Какой из трёх выходов это для вас — дайджест, или отдельный «находка-формат»?
- [ ] «Безопасно публиковать» — вы проверяете это на демо? Что именно нельзя выпускать?
- [ ] Вход: подаём сырой JSONL + `git log`, или вы заранее выделяете черновые находки?
- [ ] Канон у вас где-то записан, или это описание выше и есть канон?
- [ ] Сколько находок в посте — 1 / 3 / 5? Как отбирать, что из 511 правок достойно находки?
- [ ] Что для вас «решило» на демо: проверяемый признак?

### Цель 1 — клубный блог (Sostav и др.): SEO → Telegram → курс

Статья = вход в воронку, не самоцель. `SEO-трафик → подписка на Telegram → покупка курса`.
Канал — главный актив, курс — монетизация, статьи — способ привести людей.

- **Claude Code — тема-приманка, не суть.** Идентичность клуба = сообщество
  предпринимателей. CC берут из-за поискового спроса и низкой конкуренции —
  SEO-крючок в канал, где продаётся полная картина клуба.
- **Sostav сознательно сужен до кластера Claude Code** (05.08.2026): высокий DR
  (~55–60), индексация за сутки → быстрый предсказуемый трафик по узкой теме,
  где реально выиграть выдачу.
- **Каждая статья — на реальном кейсе участника клуба.** Соцдоказательство +
  материал, которого нет у конкурентов.
- Ресёрч 11.08: трафик статьи приносят, SEO работает. Падение роста подписчиков
  канала — вероятнее воронка (статья→канал), не число/качество статей. Слабое
  звено может быть **не в контенте**.

### Цель 2 — личный блог Тимура / GEO: попасть в ответ LLM

Когда предприниматель спрашивает у ChatGPT/Perplexity/Gemini/Алисы «в какой клуб
пойти внедрять ИИ в бизнес» — модель называет чужих (ShareAI, ЭВОЛЮТ AI), AI
Practiq в ответах нет.

- **Фаза 1:** личный блог набирает вес как источник по теме «предприниматель
  внедряет ИИ» — обычные SEO-статьи, **без упоминания клуба**.
- **Фаза 2:** когда блог наберёт доверие — статья про выбор AI-сообщества, её
  цитирует модель, приводя AI Practiq в списке.
- Отдельный канал акизиции — через ответ чат-бота, не через выдачу.

### Что это значит для инструмента

- **Многоканонность подтверждена.** Минимум 3 разных канона: `canon.sostav`
  (клубный блог), `canon.personal-p1` (личный блог фаза 1, запрет упоминания
  клуба), `canon.community-pick` (фаза 2). «Канон меняется без правки кода» —
  ровно этот кейс. `canon-lens` это уже держит (канон — файл).
- **Новые виды правил для `canon-lens` (механические, аддитивно):**
  - `require_present` — нарушение, если паттерна НЕТ (ссылка на t.me/канал; блок
    реального кейса; целевой ключ в заголовке);
  - `must_not_mention` — уже есть (`phrase_forbidden`): личный блог фаза 1 →
    запрет «AI Practiq», «клуб»;
  - `keyword_in_title` / `keyword_min_count` — SEO-ключ в заголовке и в теле N раз.
- **Судейские (→ `judge/`):** «опирается на реальный кейс», «CC связан с бизнес-
  результатом», «текст закрывает путь до подписки», «структура, которую цитирует LLM».
- Synthetic `examples/canon.md` п.7 запрещает «подписывайтесь» — а Тимуру CTA на
  канал НУЖЕН. Это разные каноны, не противоречие: его канон разрешает, просто
  не шаблонной формулировкой.
